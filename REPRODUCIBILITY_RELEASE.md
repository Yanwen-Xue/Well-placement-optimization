# Reproduction package for the 333-dimensional surrogate and NSGA-III search

This directory records the executable source snapshot and the parameter values used for the reported surrogate-assisted optimization. The large CMG property fields, `.sr3` outputs, and the site model are distributed separately when permitted; their required names and array schemas are listed below.

## Source layout

| Path | Role |
|---|---|
| `surrogate.py` | Feature concatenation, feature names, normalization, and generic XGBoost surrogate class |
| `validation_tools/train_surrogate.py` | Dataset loading and all feature-extractor construction branches |
| `validation_tools/build_static_sideview_fields.py` | Construction of the static 3-D mobility and initial-pressure fields used by the official side-view descriptors |
| `validation_tools/train_component_f3_surrogate.py` | Official F1/F2 direct models and F3 component model |
| `optimizer.py` | Hybrid NSGA-III/JADE-DE search, repair, constraints, checkpointing, and Pareto export |
| `objectives.py` | F1/F2/F3 definitions and feasibility checks |
| `cmg_runner.py` | CMG input generation, well controls, run schedule, and result extraction |
| `injectivity_prescreening_map.py` | 3-D prescreen field construction and 2-D prescreen maps |
| `validation_tools/` | Validation, extraction, ablation, plotting, and final-case utilities used after training/search |
| `cmg/2026_0421_1day.dat` | CMG input template used by the runner (the licensed SIP/property assets are distributed separately) |
| `supplementary_validation/datasources/` | Later dynamic-connectivity, grouped-contribution, timing, aggregation, raw-field, score-free, and Reviewer 8/11 validation scripts |
| `supplementary_validation/other/` | Ablation runner, baseline optimizer, and paper-figure audit scripts |

The exact values are centralized in `configs/official_333dim_training.json`, `configs/official_nsga3.json`, and `configs/cmg_simulation.json`.
The verification environment is listed in `requirements-tested.txt` (Python 3.13.9 on Windows); `requirements.txt` gives the unpinned package names for other compatible environments.

## 333-dimensional feature construction

The model input has 20 layout coordinates plus 313 deterministic geological/layout features:

* 48 plan-view, local-map, and spacing features;
* 218 static side-view features from the XZ and YZ sections, computed from normalized 3-D mobility and initial-pressure fields over the injection, production, and bridge intervals;
* 47 layout/operating features.

Thus the model input is `20 + 48 + 218 + 47 = 333` columns. The feature names are generated by the extractor and are written into the training report, so column ordering does not rely on a hand-edited table.

## Rebuild the static side-view fields

Run the following PowerShell commands from the repository root after placing the required external inputs at the paths shown below:

```powershell
$repoRoot = (Get-Location).Path
python validation_tools/build_static_sideview_fields.py `
  --property-dir "$repoRoot/property_CMG" `
  --seeds "$repoRoot/opt_seeds_0_683_current_mixed_active60_20260813.npz" `
  --out "$repoRoot/prescreen_maps/static_sideview_fields_no_pressure_threshold.npz"
```

The field builder uses the 268 x 203 x 200 grid, layers 41–80 for injection, 1–15 for production, and 16–40 for the bridge interval. Plot-only Gaussian smoothing is not used in the 218 model features.

## Train the reported surrogate

The following command uses the reported 543/136 train/test split, a separate five-fold cross-validation over all 679 successful layouts, and the XGBoost values in `official_333dim_training.json`:

```powershell
python validation_tools/train_component_f3_surrogate.py `
  --results "$repoRoot/training_data_0_683_333dim/results_0_683_current3obj_rebuilt_with_0603_0604_20260817.npz" `
  --seeds "$repoRoot/opt_seeds_0_683_current_mixed_active60_20260813.npz" `
  --model-out "$repoRoot/models/component_f3_model_0_683_static_well_triview_log.joblib" `
  --report-out "$repoRoot/models/component_f3_metrics_0_683_static_well_triview_log.json" `
  --feature-mode prescreen_geometry_local_static_well_triview `
  --test-size 0.20 --split-seed 42 --cv-splits 5 `
  --n-jobs 16 --n-estimators 800 --max-depth 2 `
  --learning-rate 0.03 --subsample 0.90 --colsample-bytree 0.90 `
  --reg-lambda 5.0 --min-child-weight 3.0
```

F1 and F2 are fitted directly. F3 is reconstructed from separate log-space models of pressure standard deviation and pressure mean, `F3 = exp(log(std))/exp(log(mean))`.

## Reproduce the reported NSGA-III protocol

The reported run used the surrogate backend, population 240, 80 generations, 12 Das–Dennis divisions (91 reference points), JADE-DE, Hungarian permutation alignment, 32 workers, and no adaptive early stopping:

```powershell
python optimizer.py `
  --seeds "$repoRoot/opt_seeds_0_683_current_mixed_active60_20260813.npz" `
  --surrogate "$repoRoot/models/component_f3_model_0_683_static_well_triview_log.joblib" `
  --pop 240 --gen 80 --ref-p 12 --parallel 32 --final-k 16 `
  --use-de --use-opt-perm-align --no-early-stop --seed 42
```

The seed 42 reproduces the saved generation-0 population exactly; the supplied `ckpt_final_population.npz`, `full_pareto_solutions.json`, and `pareto_solutions.json` are the locked numerical record of the reported run.

## CMG simulation protocol

`cmg_runner.py` generates the CMG input from the supplied template and writes the well controls. The 80-year schedule injects through year 30 and then shuts in the injectors and producers; monitoring dates continue at five-year intervals. There are five injectors completed in layers 41–80 at 288,392 Nm³ day⁻¹ per well and five producers completed in layers 1–15 with a 1,200 STW maximum and 8,000 kPa minimum BHP. Injection BHP is constrained by the Eaton fracture-pressure estimate multiplied by 0.90 and the implementation safety factor 0.99. Grid size, well geometry, numerical controls, and file names are in `configs/cmg_simulation.json`.

## Data required to execute

The executable scripts require the following data interfaces:

1. `opt_seeds_0_683_current_mixed_active60_20260813.npz`, containing the 2-D/3-D prescreen arrays, valid-cell mask, grid dimensions, layer bounds, and cell size;
2. `prescreen_maps/static_sideview_fields_no_pressure_threshold.npz`, containing `static_inj_3d`, `static_prod_3d`, and `pressure_initial_3d`;
3. the 684-row training `.npz` file with `X`, `objectives`, `success_mask`, pressure standard deviation/mean, and sample indices;
4. for full-physics execution, the CMG template, SIP file, property fields, and a licensed GEM executable.

The site model and large simulation outputs are not required to inspect the feature construction or surrogate training logic; they are required only for a full CMG rerun.

## Search-level robustness and the 10,020-dimensional benchmark

The 10,020-dimensional unaggregated column input is supplied as a matched prediction
benchmark. Under the 679-layout sample, its holdout $R^2$ values are 0.574, 0.700, and
0.326 for $F_1$, $F_2$, and $F_3$, respectively. It is therefore not used as an NSGA-III
search surrogate: a search driven by this response surface would be dominated by prediction
error, especially for $F_3$. The search-level robustness test uses the matched 301-dimensional
score-free input, which removes the direct prescreen-score descriptors while retaining the
layer-resolved geological variables and layout descriptors. The corresponding search checkpoint
and comparison tables are included in the release records.
